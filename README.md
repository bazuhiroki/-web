# 執事 (Shitsuji)

個人用のAIエージェント。スマホにポップアップで出てきて、指示すると調べて返す。

最初の仕事は「メルカリで、自分の体格に合う服を予算内で探す」。

---

## 制約から決まった設計

三つの制約が、ほぼすべての設計判断を決めている。

| 制約 | 帰結 |
|---|---|
| インフラ費 **0円**（月500円の全額をAPIに回す） | サーバーを持たない。エージェントのループも、スクレイピングも、全部Android端末の中で動く |
| 月 **500円** の上限 | Haiku 4.5 を常用機に。絞り込みは決定的な計算でやり、LLMには要約しか渡さない |
| Android | 画面操作もできるが、**Webで叩けるものはWebで叩く**を原則にした |

### サーバーを持たないことの副産物

- メルカリに、本人の回線・本人のUA・本人のログインセッションでアクセスする（データセンターのIPからの機械的アクセスにならない）
- 体格・所持品・APIキーが端末から出ない
- 期限切れになるホスティングも、更新が必要な証明書もない

## コスト設計

月500円 ≈ $3.3。これに収めるために三段構えにしている。

**1. LLMに渡す前に、決定的な計算で絞る**

検索結果30件の説明文をそのままモデルに渡すと、1回の検索で15,000トークン飛ぶ。
代わりに:

```
検索 → 正規表現で実寸を抽出 → 体格レンジと突合 → スコア順に並べる  ← ここまでLLM 0トークン
   → 上位10件の「要約1行」だけをモデルに渡す                        ← 約1,500トークン
```

日本語の出品説明文の実寸表記（`肩幅：42cm`）は驚くほど定型なので、正規表現で大半が取れる。

**2. プロンプトキャッシュの閾値を逆手に取る**

Haiku 4.5 は、システムプロンプトが **4096トークン未満だとキャッシュが黙って効かない**。
エラーも警告も出ず、ただ毎回フル単価を払う。

なので、システムプロンプトを意図的に4096トークン超まで厚くしている。
詰め物ではなく、**判断ルーブリックと本人のプロフィール**で埋める。結果:

> プロフィールを詳しく書くほど、判定が良くなり、かつ安くなる。

アプリ内の「いま何トークンか測る」ボタンで、閾値を超えているか確認できる（測定は無料）。

**3. 実測ベースの上限**

見積もりではなく、レスポンスの `usage` を積んで課金額を計算する。
上限に達したらエージェントは停止する。

### 実測の目安（1往復あたり）

| 内訳 | トークン | 費用 |
|---|---:|---:|
| キャッシュ済みプレフィックス | 4,200 | $0.00042 |
| 新規入力（履歴＋ツール結果） | 3,000 | $0.0030 |
| 出力 | 600 | $0.0030 |
| **計** | | **約 $0.0064（約1円）** |

→ 1日10回使って月300〜500円。上限内に収まる。

## 「似合う」をどう判定しているか

出品の `M` / `L` というサイズ表記は当てにならない。ブランドと年代で3〜5cmずれる。

効くのは**実寸**と、**本人の「当たり服」の実寸**との比較。

```
プロフィールに登録:
  無印 ネイビーカーディガン  肩幅44 身幅52 着丈68  → ちょうど良い
  ユニクロ グレー            肩幅45.5 身幅54 着丈70 → 許容範囲

→ 適正レンジを自動導出: 肩幅 42.5〜47.0 / 身幅 50.5〜55.5 / 着丈 66.5〜71.5

→ 出品説明文から実寸を抽出して突合、部位ごとに重み付けしてスコア化
```

部位の重みは同じではない。**肩幅が2cmずれると、他が全部合っていても着られない**。
袖丈は多少長くてもまくれる。この非対称性がスコアに入っている。

実寸が書かれていない出品は落とさないが、「実寸なし」と明示して下に置く。

## やらないこと

**購入・オファー・入札・支払いを自動実行しない。** 候補を出して並べるところまで。
ボタンを押すのは必ず人間。

これは技術的な制約ではなく方針で、システムプロンプトにも明記してある。
メルカリの規約上グレーであること、アカウント停止のリスクがあること、
そして「間違えたときに取り返しがつかない」ことが理由。

## 使い方

### 1. APKを入れる

Android Studio は要らない。GitHub Actions がビルドしている。

1. このリポジトリの **Actions** タブ
2. 最新の成功した `Build APK` を開く
3. Artifacts から `shitsuji-debug-apk` をダウンロード
4. 展開して端末にコピー、提供元不明アプリを許可してインストール

### 2. APIキーを入れる

[console.anthropic.com](https://console.anthropic.com) でキーを発行し、設定タブに貼る。
端末のKeystoreで暗号化して保存される。

### 3. プロフィールを書く ← **ここが一番効く**

プロフィールタブで「記入例を入れる」を押し、自分の数字に書き換える。

**手持ちで「これは似合う」と思う服を、メジャーで測ってください。**
カテゴリごとに2〜3着。肩幅・身幅・着丈。

この30分が、コードの1週間分より効きます。

### 4. ポップアップの出し方

| 方法 | 対応 |
|---|---|
| クイック設定に「執事」タイルを追加 | 全機種 |
| 設定 → 既定のアプリ → デジタルアシスタント → 執事（電源ボタン長押し） | 機種による |
| 任意のアプリで文字を選択 → メニューの「執事」 | 全機種 |

## 既知の弱点

**スクレイパは検証されていない。** 開発環境から `jp.mercari.com` に到達できなかったため、
DOM構造に対する実地検証ができていない。以下で備えている:

- CSSクラスや `data-testid` ではなく、`/item/mXXXXX` という**URL形式**を手がかりにしている。
  クラス名はリニューアルのたびに変わるが、URLの形は外部仕様なのでめったに変わらない
- 診断タブで、実際に取れたHTMLを確認できる
- 抽出スクリプトは設定から差し替えられる（APK再ビルド不要）

最初に動かして0件だったら、診断タブの出力を見れば原因がわかる。

**ログインが必要な場合がある。** 端末のChromeでメルカリにログインしていても、
アプリ内WebViewはCookieを共有しない。初回は検索が制限される可能性がある。

## 構成

```
agent/
  Agent.kt          tool use のループ（手書き、60行）
  Anthropic.kt      Messages API の最小クライアント
  Budget.kt         モデルの値段と月次の上限
  SystemPrompt.kt   システムプロンプト組み立て（4096トークン超を狙う）
  Tools.kt          ツール3つの定義とディスパッチ
tools/
  Mercari.kt        検索・絞り込み
  WebScraper.kt     画面外WebView
  SizeExtractor.kt  実寸の正規表現抽出
  FitScorer.kt      体格突合スコアリング（LLMを呼ばない）
data/
  Profile.kt        体格・当たり服・好み
  Store.kt          DataStore + 暗号化Prefs
ui/                 ポップアップ・設定・診断
```

公式の `com.anthropic:anthropic-java` を使っていないのは意図的。
jackson-databind と Apache HttpCore 5 を引き込むサーバーJVM向けで、APKに入れると
R8のkeepルールとメソッド数で割に合わない。必要なのは `/v1/messages` 一本だけ。
Android向けの公式SDKは存在しないので、ここは生HTTPが正しい。
